# Architecture

Jewbuntu is an **overlay of Debian packages on a supported Ubuntu LTS release**.
Ubuntu owns the kernel, bootloader, installer, drivers, desktop shell, security
updates and release upgrades. Jewbuntu owns a small, versioned set of packages and
the per-user data they create.

```text
             +-------------------------------------------------------------+
  user       |  ~/.config/jewbuntu/settings.json   (schema-versioned)      |
  (XDG)      |  ~/.local/state/jewbuntu/backups/   (verified backups)      |
             |  ~/.cache/jewbuntu/                 (disposable)            |
             +---------------------------^---------------------------------+
                                         | read/write as the user only
 +-------------------+   D-Bus (M2)   +--+------------------+    +--------------------+
 | jewbuntu-gnome    | <------------> | jewbuntu-jewish-    |    | jewbuntu-core      |
 | thin panel ext.   |   versioned    | service (M2, GJS)   |    | `jewbuntu` CLI,    |
 | (GNOME-version    |   interface    | calendar, zmanim,   |    | config + migrations|
 |  specific)        |                | Shulgo adapter      |    | doctor, matrix     |
 +-------------------+                +--+------------------+    +--------------------+
          | opens                        ^                              ^
          v                              | D-Bus                        |
 +-------------------+                   |                    +--------------------+
 | jewbuntu-hub (M2) |-------------------+                    | jewbuntu-upgrade-  |
 | standalone GTK4/  |   works with the extension disabled    | tools: readiness,  |
 | libadwaita app    |                                        | repo enrollment    |
 +-------------------+                                        +--------------------+

 jewbuntu-desktop  = metapackage + vendor gsettings override (defaults only)
 jewbuntu-branding = wallpapers, startup jingle (XDG autostart, once per boot)
 jewbuntu-hebrew   = input sources default, nikud fonts, fontconfig preference
```

## Boundaries that protect upgrades

| Concern | Lives in | Why |
| --- | --- | --- |
| Calendar maths, Shulgo polling, caching, credentials, migrations | Service / core (outside GNOME Shell) | A shell crash or GNOME API change cannot lose data or freeze the desktop |
| Panel indicator | `jewbuntu-gnome`, rebuilt and re-tested per GNOME major | GNOME extensions break across shell versions. Only tested versions are declared in `metadata.json`. |
| Look and feel | GSettings vendor override (`90_jewbuntu-*.gschema.override`) | Changes *defaults* only. User choices win. Removing the package restores Ubuntu's defaults. No theme hacks, no patched libraries. |
| Per-user data | XDG directories, written only by user processes | Root maintainer scripts never touch homes. Migrations run as the user (`jewbuntu-migrate.service`, a systemd *user* unit). |
| Machine config | `/etc/jewbuntu/` conffiles | Normal dpkg conffile handling |
| APT source | Generated by `jewbuntu repo enroll`, not a conffile | It must be rewritten for the running codename after a release upgrade. Enrollment is gated by `support-matrix.json`. |

## Runtime choices (see `docs/decisions/`)

- **Python 3 (standard library only)** for core, doctor and upgrade tools. It is present on every Ubuntu install, with no pip dependencies.
- **GJS** (planned, M2) for the service, Hub and extension. It is already on every GNOME system, so no extra runtime is needed on old hardware. The Hebcal library is bundled once as an ES module and tested under both Node (fast unit tests) and GJS (smoke tests).
- **D-Bus session bus** (planned, M2) as the IPC, with a versioned interface name.

## Settings lifecycle

1. Packages install defaults in code. Nothing is written to a home at install time.
2. The first write (`jewbuntu config set`, onboarding, Hub) creates `settings.json`
   containing only the values the user changed.
3. A package upgrade that raises `SCHEMA_VERSION` ships a migration. At the user's next
   login, `jewbuntu-migrate.service` backs up the old file (verified copy), writes the
   migrated file atomically, and keeps unknown keys. Readers migrate in memory, so a
   missed migration never breaks reading.
4. A file from a *newer* schema (for example after a downgrade) is read-refused and never overwritten.
5. `apt remove` / `apt purge` never delete user data. `jewbuntu reset` lists everything first and exports a final backup.

## Release and repository model

Per supported Ubuntu suite: `dists/<codename>/main` (stable) and
`dists/<codename>-testing/main`. Package versions carry the Ubuntu release
(`0.1.0~m1.2+26.04`), so builds for different releases never collide and a later
release's build sorts higher. The repository is trusted only via `Signed-By`.
An APT pin (`Pin-Priority: -1` for everything except `jewbuntu-*`) stops the origin
from ever replacing Ubuntu packages. The container test proves this with a decoy
`base-files`.
